# 货到付款与物流下单

第一阶段已实现。物流商下单 API、自动签收推送及自动结算对账尚未接通。当前使用通用 CSV 下单资料表、运单回填和人工核实。

## 新订单付款方式

后台“客户管理 → 管理设置”增加“货到付款”模式。切换只影响后续订单，历史测试及预先付款订单保持原有类型和状态。

货到付款结账页明确提示收货时向物流商付款，不在线扣款。收货电话必填，省/州可录入；US、CA、AU、IN 需填写省/州，原有邮编规则继续生效。各物流商的可配送国家和可代收币种尚未配置，发货前须核实。

## 客户下单资料自动同步

后台订单详情“货到付款 · 发货资料卡”自动带入客户下单时的收件人、电话、邮箱、国家、省/州、城市、地址、邮编，以及商品规格、数量和代收金额。

点击“一键复制收货信息”即可粘贴到物流商下单页面。复制在本机剪贴板执行，不会自动把客户资料发送给物流商。

确认发货资料时，可以更正收件人、地址、电话、代收金额及币种；原始下单资料保留，发货资料另存快照，更正前后内容有审计记录。代收金额或币种与订单不一致时，必须填写换算或差额说明，系统不会自行猜测汇率。

## 物流表导出与回填

1. 打开待确认订单，核实配送资料和代收金额，保存“确认并保存发货资料”。确认后即可发货，无需先收款。
2. 在订单列表选择已确认、待发货订单，点击“导出所选订单的物流下单表”。也可从单个订单详情导出。
3. CSV 为 UTF-8，可用 Excel 打开，最多一次500个订单。包含订单号、收货信息、商品信息、代收金额及币种；有防公式处理。该表是通用资料表，需根据实际物流商格式调整列名及映射。
4. 物流商出单后，进入“批量回填运单”，下载模板，将结果整理为四列：`order_id,tracking_number,carrier,carrier_name`。
5. 选择 CSV 文件或粘贴 CSV 文本，提交后逐行匹配并回填。成功行创建包裹并标记发货；重复的同一订单、单号及物流公司跳过；匹配不到、未确认或错误行显示失败原因。可以只修正失败行后重试。

通用回填用于订单首个包裹；拆包或补充包裹在订单详情管理，避免不知道商品和代收金额分配就自动新增包裹。

## 多包裹与代收金额

发货首包默认包含全部商品及全部核定代收金额。拆包时先减少首包的商品和代收金额，再添加剩余包裹。所有包裹的商品合计不能超过订单数量，代收金额合计不能超过订单核定金额。

包裹允许零代收金额，例如同一订单只在一个包裹代收。填写代收金额时要与物流商下单结果一致。已签收、拒收、退回、已核实代收或已入库的包裹不能再修改商品、运单和代收金额。

## 签收、代收和回款分开核实

包裹签收与代收区提供运输中、派送中、签收、物流异常、拒收、退回途中及已退回登记，必须填写核实依据和时间。重复或无效的状态转换会被拒绝。时间输入使用北京时间。

- **签收**：只更新包裹配送情况，不改变付款状态。部分签收会显示提示；包裹和商品全部覆盖并签收后才记录订单整体收货时间。
- **核实代收**：只有已签收包裹可以登记；实际代收金额须等于该包裹核定金额，存在差异先向物流商核实。登记后显示待回款。
- **核实回款**：填写本次结算的代收货款、扣费、参考号、到账时间，并确认实际到账。系统分别保存结算金额、费用及净实收；不能超过已核实代收但尚未结算的金额。分次回款累计，重复请求或重复参考号不会记两次。
- **退回入库**：拒收或退回途中不恢复库存。只有已退回且实际入库、验收确认后恢复包裹商品库存，一次包裹只恢复一次。

已签收后的售后退货、退款以及代收金额差异更正，目前需通过客户售后跟进并人工核对，第一阶段不自动处理这些财务调整。

付款状态 `paid` 表示原核定代收金额已经全部结算确认；扣费另记，不会伪造净回款等于订单金额。部分拒收/退回订单保留部分回款记录，不能当作原金额全额回款。

## 后台提醒

订单管理和概览显示待确认、待发货、待签收、签收待核实代收、待回款、物流异常及超过3天无更新的数量。页面打开时每15秒刷新数量；点击进入对应订单列表。队列按当前待处理事项归类，处理后自动更新，没有重复创建提醒。

这不是自动物流追踪：包裹签收和异常目前通过人工登记获知。后台没有接到物流商数据时，不会猜测已签收；没有接到收款和实际回款证据时，不会猜测已付款。没有新增邮件、短信或 WhatsApp 自动提醒。
