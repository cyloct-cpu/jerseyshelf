# 前台商品热度展示

2026-10-15 已按授权方案完成，适用于全部商品详情及后续新增、导入商品。

## 当前行为

- 购买区域下方显示“商品热度（展示值）：N”。英文界面明确显示 `Product interest (simulated)`，其它语言使用现有翻译回退规则。
- 初始展示值为 200–1000 的整数。每 8–15 秒更新一次，每次增减 3–15；触及范围边缘时向内变化。
- 数字不采用动画，不使用实时播报，避免频繁打扰阅读。浏览器禁用 JavaScript 时隐藏该动态展示区域。
- 同一标签页按商品保存展示状态，30 分钟内刷新沿用原值。使用 `sessionStorage`，键名为 `bw_product_heat_demo_v1:商品ID`；不同商品的状态互不覆盖。
- 隐藏页面时暂停，恢复可见时继续；离开页面清理计时器，浏览器前进/后退缓存恢复时可重新启动。重复启动不会增加计时器。
- 存储禁用、配额不足、数据损坏或过期时自动重新生成或使用页面内存，不影响商品购买。

## 真实访问统计

随机展示值不是在线人数，不发送到 `/api/traffic`，不写入统计表，不参与推荐排序、销量、库存和订单计算。

原有 `store.js` 的进入、15 秒心跳、离开事件及后台的 45 秒在线判断继续执行。后台仍统计真实匿名浏览器访客、页面访问、商品访问和在线人数。浏览器验收访问本身会按原规则计入真实访问。

本次没有新增数据库字段或迁移，没有改动 `apps/api/traffic.mjs`、`apps/admin/traffic.mjs` 或原有统计脚本。受保护文件前后哈希见 `data/manifests/product-heat-change.json`。

## 文件规划与调整

- `packages/contracts/product-heat.mjs`：集中配置 `HEAT_CONFIG`，包含数值范围、步长、更新间隔和 30 分钟保留时间，以及存储校验、计时器逻辑。
- `apps/storefront/product-heat.mjs`：商品页展示文案和独立容器。
- `apps/storefront/public/product-heat.js`：浏览器加载、页面可见性和生命周期接入。
- `apps/storefront/public/store.css`：独立 `.product-heat` 样式。
- `apps/api/server.mjs`：仅为新模块添加静态文件路由，没有增加统计接口或后台设置。

修改范围或频率时，调整 `HEAT_CONFIG` 并同步 `tests/product-heat.test.mjs` 中的业务边界检查。使用说明不应把模拟展示值称为真实人数。

如需恢复前台真实在线人数：将商品页的 `productHeat(p)` 替换为原真实人数容器，使用 `currentTraffic(p.id).productOnline` 作为初始值，并保留 `data-live-viewer-count` 属性。原 `store.js` 已保留真实人数更新支持；移除模拟组件引用即可，无需数据库回滚。
