# 真实用户体验测试计划

日期：2026-10-15。阶段：本地商城验收，先制定计划。

## 目标和范围

按首次到访顾客、购买定制球衣的顾客、回访顾客和处理订单的店主四种身份，走完整流程，找出让人看不懂、不敢买、买不了或订单处理出错的问题。

测试入口为 `http://127.0.0.1:3001/`，后台为 `/admin`。没有域名和服务器不影响本轮执行。本轮不部署、不接真实支付、不发真实邮件，也不以是否接入这些服务判断本地流程是否通过；另列正式营业前缺项。

本文件依据源码与现有文档编写，尚未开展本轮浏览器验收。过去的测试记录只能作参考，不能替代本轮结果。

## 已发现的缺项及核实重点

| 项目 | 初查依据与状态 | 如何处理 |
| --- | --- | --- |
| 真实收款和退款 | 结账页、订单状态和后台只支持本地测试付款/退款 | 本轮完整走模拟闭环；正式接入在后续阶段单列 |
| 找回密码 | 当前登录页没有入口，已检查的账户路由未实现此流程 | 列为账户功能缺项；本轮测注册、登录、退出与错误提示 |
| 邮件通知 | 使用说明记录未接邮件；订阅接口仅保存邮箱 | 核实页面提示是否准确，单列注册/订单/发货通知与订阅发送缺项 |
| 政策正文 | 路由对缺失政策提供“正文待导入”占位；使用说明记录未导入 | 实测当前页面；退换货、隐私、服务条款及配送说明需按实际经营内容补齐 |
| 联系客服 | WhatsApp 暂留空，页脚联系入口依赖客服邮箱配置 | 核实顾客是否找得到有效联系方式，以及商品描述中的联系提示是否可用 |
| 规格、库存和可购买性 | 文档记录部分原站规格待核实、运营库存需维护 | 统计实际可购买比例，不能把“商品页存在”视为“可以购买” |
| 超时未付款订单 | 使用说明记录创建订单即扣库存，暂无自动超时释放 | 本轮验证取消恢复库存；另列库存占用期限和自动释放机制 |
| 翻译完整性 | 自动翻译已实现，但免费额度与回退机制可能留下原文 | 优先验收中文/英文全流程；其他语言抽查，记录混语和失败回退 |
| 文档与运行状态 | README 部分段落仍写“尚未接翻译”，后文又记录已接入；翻译说明端口与主入口不一致 | 运行状态以实际测试为准，后续同步维护说明 |

上述源码中存在的占位/未实现，与数据库里当前是否已补内容分开记录；未读取当前配置或未操作的项目不写成已确认故障。

## 执行顺序

### 1. 准备可重复的测试环境

- 确认本地服务启动方式、当前端口和首页可达性。
- 先确认已有备份可用；创建独立测试数据库与必要媒体配置，使用真实目录的副本走写入流程。运营库只做浏览和必要的只读统计。
- 测试账号、商品、订单统一加 `QA` 标记；使用虚构收件信息。不改现有商品的实际价格、库存、翻译设置和运营订单。
- 准备可购普通款、国家队款、俱乐部款、缺货款、最后一件库存和超长标题商品；准备带印字与多臂章的组合。
- 在隔离环境运行现有自动测试，保存当前结果；浏览器检查专门关注用户体验和跨页面流程。

### 2. 按顾客路径走完整购买流程

| 环节 | 用户操作 | 验收重点 |
| --- | --- | --- |
| 首页 | 首次访问、轮播、导航、国家队/俱乐部菜单 | 清楚卖什么，主入口可点，图片可见，手机菜单可关闭 |
| 找商品 | 搜球队、中英文别名、无结果词；筛价格、排序、翻页 | 结果符合意图，筛选条件保留，无结果有继续浏览入口 |
| 看商品 | 看主图与缩略图、尺码说明、材质/发货/退换说明 | 图片清晰，信息一致，价格、可选规格、库存状态清楚 |
| 做定制 | 选择尺码、输入印字、选择/取消臂章 | 必填与长度限制明确，加价及时更新，不同定制不会错误合并 |
| 购物车 | 加购、重复加购、改数量、删除、刷新和返回 | 商品、尺码、印字、臂章均保留，数量与金额同步 |
| 优惠与运费 | 分别测试 2/3、7/8、9/10 件及实际免邮门槛前后 | 最高档规则、免邮和币种换算正确，商品页/购物车/结账/订单一致 |
| 结账 | 游客与注册用户填写地址，提交测试订单 | 提示明确；表单报错能改正；重复点击不重复生成订单 |
| 订单后续 | 看订单、登录后看订单列表、刷新与返回 | 订单快照完整，能了解当前状态，不泄露他人订单 |
| 店主处理 | 后台核对定制，模拟付款、发货、取消及退款 | 信息可直接用于处理订单，状态正确，库存只扣/恢复一次 |
| 回访 | 退出/登录、最近浏览、推荐、联系客服、订阅 | 信息可找到，反馈明确，不能将模拟热度或订阅保存误解为实际服务能力 |

### 3. 跨设备与异常情况

- 桌面约 1440px、手机 390px 与窄屏 360px，平板 768px；检查横向溢出、图片比例、按钮遮挡、表单和菜单操作。
- 中文与英文走完购买流程；额外抽查一种非英语语言和一种 RTL 语言。切换语言不应清空购物车或误改币种。
- 使用 USD 和另一种已支持币种对照完整金额；抽查零小数币种的显示与取整。记录汇率来源和时点，避免将缓存报价当作实时承诺。
- 测空购物车、缺货、超库存、商品下架、定制配置变更、报价过期、无效邮箱和空地址。
- 测双击提交、刷新订单页、浏览器后退、两标签页同时操作，以及最后一件商品的竞争下单。
- 测慢速加载、图片失败、翻译不可用和浏览器存储受限时是否仍可理解和继续操作。
- 查看键盘焦点、表单标签、错误提示及图片替代文字等基础可用性。
- 检查未登录后台访问、跨账号订单访问和非预期错误页面；敏感信息不进入报告截图。

### 4. 商品与内容抽样

全目录用只读方式统计商品总数、启用状态、可购规格、库存、图片路径及分类关联。浏览器先抽查不少于 20 件，覆盖不同球队/国家队、赛季、服装类型、价格、长标题、缺货和定制组合。

抽样用于发现共性体验问题，不代表 4,166 件商品逐件人工验收。发现模板共性问题后，再通过目录扫描或扩大抽样确认影响范围。

### 5. 性能与本地可用性

记录首页、分类、搜索、详情和购物车的首次加载与重复加载表现，关注大图阻塞、菜单迟钝和列表图片加载。每类至少取三次观察并记录设备与环境。

本地测试用于发现明显瓶颈，不能据此承诺公网加载速度、并发容量、HTTPS、邮件送达或真实支付回调可靠性。

## 问题分级与交付

- P0：金额错误、库存错误、重复订单、订单/后台数据越权。优先处理并暂停受影响流程验收。
- P1：无法购买、关键按钮失效、手机无法操作、定制丢失、关键内容无法理解。
- P2：布局、提示、搜索体验、性能、推荐和内容完善问题，不阻塞主要流程。
- 正式营业依赖：域名、服务器、HTTPS、真实支付、邮件、配送服务等单独列出，避免与本地程序故障混为一谈。

每条问题记录：编号、级别、页面、设备、账号身份、复现步骤、期望结果、实际结果、截图或日志证据、影响范围、建议和修复后复测状态。

交付《真实用户测试报告》，包含：完成/失败/阻塞的场景、具体问题清单、确定缺少的能力、需店主提供的信息以及修复顺序。测试数据在隔离环境保留到复测完成，便于重现。

## 本地阶段完成标准

1. 手机和桌面均完成“找商品 → 选择规格/定制 → 购物车 → 测试下单 → 后台处理”的流程。
2. 抽查组合的商品价、定制费、满件优惠、运费及货币金额在各页和订单快照保持一致。
3. 重复提交、库存不足、取消/模拟退款和访问权限验证有明确结果，无未解决的 P0/P1 本地功能问题。
4. 占位内容、翻译空缺和待接服务有完整清单；不把模拟支付通过写成可以正式营业。

计划确认后的下一步是执行本地验收并出报告。修复按实际结果排序，域名与服务器留到部署阶段处理。
