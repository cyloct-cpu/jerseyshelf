# 前台商品热度展示计划

日期：2026-10-15。状态：已按用户授权完成并验收，见 [前台商品热度展示](前台商品热度展示.md)。下文保留原实施方案。

用户提出前台数字在 200–1000 间变化，后台继续保留原有真实统计。随机数属于模拟展示值，不能称为“当前真实在线人数”。本方案将模拟展示与真实统计分开，前台明确使用“商品热度（展示值）”。

## 1. 前台文案与位置

- 使用商品购买区域下方现有人数提示的位置。
- 文案改成“商品热度（展示值）：528”，不使用“528 人正在浏览”等实时人数表述。
- 所有商品详情页统一生效，后台新增商品同样适用。
- 数字仅作页面展示，不参与库存、销量、推荐排序、优惠或订单金额。

## 2. 数字变化规则

1. 初次进入页面，在 200–1000 范围生成一个展示值。
2. 每隔 8–15 秒变化一次，每次增加或减少 3–15，限制在 200–1000。
3. 临近边界时向区间内调整，不出现越界、负数或频繁的大幅跳变。
4. 同一标签页短时间刷新可沿用当前商品展示值，避免立即出现完全不同的数字；记录仅放 sessionStorage，并标明是展示状态。
5. 标签页隐藏时暂停，恢复可见后继续；离开页面时停止计时。
6. 存储不可用时使用当前页面内存，正常显示，不影响商品页加载。

## 3. 后台真实统计保持现状

- 保留真实访客、商品访问量、在线人数及按北京时间统计的规则。
- 保留现有页面进入、心跳、离开事件及去重方式。
- 前台模拟数字不提交到统计接口，不写入数据库，不作为后台在线人数。
- 本次不新增后台统计字段，不修改历史数据、访问统计界面和商品推荐的真实访问排序。

## 4. 文件与维护

- 新建 `apps/storefront/public/product-heat.js`，集中管理展示区间、更新时间与变化幅度。
- 商品页模板提供独立的展示容器，真实统计脚本继续执行原有采集。
- 必要样式放入现有 `store.css` 的独立区块。
- 增加使用说明，注明数字为模拟展示状态，并列出恢复前台真实在线人数的方式。

## 5. 实施顺序

1. 核对现有真实统计脚本与人数容器，确保展示逻辑可独立替换。
2. 添加热度展示组件与明确文案。
3. 实现有界更新、页面可见性暂停及刷新状态保留。
4. 验证后台数据仍由真实进入和点击产生，模拟变化不新增访问事件。
5. 验证桌面、手机、刷新、切换商品和存储受限场景，保存验收截图。

预计无需数据库迁移或重新采集商品图片。服务器和域名部署继续暂缓。

## 6. 验收标准

- 每件商品详情都显示明确标注的展示值，始终处于 200–1000。
- 数字按设定的小幅度变化，后台真实访问统计不受影响。
- 页面隐藏时不继续更新；返回页面、刷新或切换商品后无重复计时器。
- 定制选项、购物车、订单、推荐和最近浏览继续正常运行。
- 本计划已执行；前台显示明确标注的模拟热度，后台继续真实统计。
