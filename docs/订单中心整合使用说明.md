# 订单中心

原“订单管理”和“售后与对账”已整合到 `/admin/orders`，侧栏只保留“订单中心”。本轮调整展示、导航、统计和操作入口，现有订单、包裹、售后单、退款、回款和审计记录保留，不迁移或删除账目。

## 五个标签页

| 标签 | 使用场景 |
|---|---|
| 全部订单 | 搜索全部订单、导出已确认待发货的物流下单表、批量回填运单 |
| 待确认与跟进 | 未确认订单、今日/逾期联系、负责人、联系结果与资料确认 |
| 发货与物流 | 待发货、运输中/待签收、异常、超过3天未更新 |
| 代收与回款 | 签收待核实代收、待回款及待处理差额 |
| 售后处理 | 售后审核、退货验收、退款、换货/补发、已结束申请 |

六项顶部待办共用一个统计源：待确认、今日跟进、待发货、物流异常、待回款、售后待处理。每15秒刷新数量。前五项按订单计数，售后按未完成申请计数；同一订单可能出现在不同业务待办中，不将数字相加作为总订单数。

待确认表示尚未核实订单资料；今日跟进依据下次联系时间。资料确认后同步退出待确认，进入待发货。签收、物流实际代收、商家实际回款仍分开核实。实际代收已登记但存在差额时进入差额处理，不继续当作“尚未核实代收”。

## 一个订单详情入口

订单详情分为商品与客户、跟进与确认、包裹与物流、代收与回款、售后处理、操作历史。

- 在“跟进与确认”记录联系及核实发货资料，一键复制收货信息、导出单个订单物流表。
- 在“包裹与物流”登记首个运单、发货、包裹拆分、更正、签收、拒收和退回验收入库。取消未发货订单也在此处理。
- 在“代收与回款”登记物流实际代收及更正、差额单、回款和实际私下转款。本页是唯一可见的代收金额登记入口。
- 在“售后处理”创建及打开申请，原售后处理表单、私有证据、验收、换货及退款校验继续有效。
- 在“操作历史”汇总跟进、COD、商品售后、包裹更正及预先付款流水。历史明细不会被重写。

预先付款和测试订单保留原来的鉴权及状态规则，相关操作放入对应标签。库存与退款等校验继续使用原业务模块。

## 旧链接

`/admin/service` 跳转到订单中心的售后标签，原 `view` 参数映射到相应标签和筛选。`/admin/service/:id` 跳转到对应订单详情的售后申请，保留提交后的提示消息。旧统计JSON接口保留字段兼容，数据由统一订单中心模型计算。原POST接口继续处理现有表单及保护校验。

业务规则仍在“待确认与跟进”或“售后处理”底部维护。国家选择、货到付款方式、物流商私下回款模式及自动接口的现有接入状态不受本次整合影响。

## 验证

新增专项验证覆盖：待办只显示一套、确认后计数变化、确认与发货分区、代收只显示一个登记入口、旧链接跳转、跨订单售后申请被拒绝、统计鉴权。原COD、退货退款、库存及物流查询回归继续执行。
