# 订单跟进页地址解析修复

已于 2026-10-19 发布。尚未确认发货资料的货到付款订单，打开跟进或物流标签曾返回“数据格式错误”。`getOrder()` 已将原收货地址解析为对象，`shippingAddress()` 却再次调用 `JSON.parse()`，引发异常。

`apps/api/cod.mjs` 的地址读取现在同时接受数据库中的 JSON 文本与订单详情中的对象，仍优先使用已确认的发货地址。未更改生产订单或客户数据。

验证：`node --test tests/cod.test.mjs` 共 7 项通过；新增未确认地址订单的六个详情标签访问断言，并验证跟进页显示原地址。发布后通过正式域名验证问题订单六个标签，全部返回 HTTP 200。

线上仅替换 `apps/api/cod.mjs` 并重启服务，旧文件备份在 `/opt/jerseyshelf/patch-backups/cod-before-address-object-20261019.mjs`。
