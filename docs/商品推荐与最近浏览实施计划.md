# 商品推荐与最近浏览实施计划

日期：2026-10-15（北京时间）。本计划已按用户授权实施并验收，使用方式与结果见 [商品推荐与最近浏览](商品推荐与最近浏览.md)。下文保留原始方案及实施前基础记录。

## 1. 目标与当前基础

在全部商品详情页的商品描述后、页脚前依次增加：

1. “您可能也喜欢”：按当前商品自动推荐相关商品。
2. “最近浏览”：展示当前浏览器实际查看过的商品。

桌面参考用户提供的两张截图，默认每个模块展示 6 件商品，分成两排模块，每个模块桌面为一行 6 张卡片。卡片包含方形原图、左下角红色销售标记、商品名称、红色售价、划线原价和独立优惠金额框。点击图片或标题进入该商品详情，继续选择尺码、印字和臂章。

已核对本地基础：

- 当前有 4,166 件上架且有图的商品，分类含 65 个俱乐部、45 个国家队和 28 个其它分类。
- `apps/storefront/views.mjs` 已有统一商品卡片、原图缩略副本、多语言商品名和币种换算，可继续复用。
- 详情页目前没有这两个模块，也没有个人最近浏览功能。
- `traffic_views` 是全站访问统计，包含多次页面进入，当前没有个人浏览列表的排序、保留期或清除功能。个人历史使用独立记录。
- 当前自己的可售库存商品数为 0，因此推荐默认按“上架、有图”过滤，缺货商品仍能展示；购买状态由现有库存校验处理。

本计划依据截图及本地实现制定，尚未实际核验原站这两个模块的完整排序算法、历史保留期和手机交互。下列规则是新站的明确实施方案。

## 2. “您可能也喜欢”的推荐规则

### 候选与排序

默认展示 6 件，按以下顺序填充：

1. 后台为当前商品指定的推荐商品，按管理员排序优先展示。
2. 同一俱乐部或同一国家队的相关款式，如同队主场、客场、球迷版和球员版。
3. 同类型/同系列商品，结合已维护的儿童、复古、风衣、短裤及赛季分类。
4. 仍不足时，用相关分类中的近期真实访问较多商品补充；数据不足则按稳定的上架顺序补齐。

推荐时优先照顾服装类型及儿童分类。例如球衣页优先球衣、儿童页优先儿童商品、风衣页优先相应外套。赛季作为辅助条件，权重低于球队和明确的服装分类。分类资料不足时使用通用兜底，后台可手动指定更合适的商品。

### 筛选边界

- 排除当前商品 ID；按稳定商品 ID 去重，同一商品的不同尺码只出现一张卡片。
- 仅展示上架且有图的商品；手动推荐中被下架的商品也自动过滤，再用候选补足。
- 不同商品的球迷版和球员版可各自展示，保留原有商品身份。
- 分别对两个模块内部去重；推荐与最近浏览之间允许有同一商品，符合两种用途。
- 同等条件使用固定顺序，避免刷新时无规律跳动。
- 缺货商品默认可展示，后台可选择“仅推荐有库存商品”。打开该选项且不足时按实际数量显示。
- 不为凑满 6 件而显示当前商品、重复卡片或未上架商品。

服务端先生成推荐列表，商品页直接渲染，顾客打开页面即可看到。后续后台新商品参与同一规则，无需逐页添加模块。

## 3. “最近浏览”的记录规则

### 默认行为

- 游客即可使用，按当前浏览器保存；第一阶段不要求登录或跨设备同步。
- 只在有效商品详情页实际进入可见状态时记录，列表按浏览时间倒序。
- 重复查看同一商品时移到第一位，保留一个记录；不同网址别名通过同一商品 ID 合并。
- 参考截图，默认包含当前正在查看的商品，放在第一位。
- 保存最近 30 件、最多保留 30 天，前台默认展示最近 6 件；不足 6 件就显示实际数量。
- 提供“清空最近浏览”，点击后清除当前浏览器记录并更新模块；不影响购物车或订单。
- 读取其它标签页的记录变化，保持同一浏览器下的列表同步。

### 保存与展示

采用有版本号的浏览器本地记录，例如 `bw_recent_products_v1`，仅保存 `{ productId, viewedAt }`。

图片、名称和价格每次从新站获取当前公开数据，因此后台修改价格、替换图片或切换币种后，卡片能显示最新内容。已下架、删除、不存在或无图的商品会过滤，不展示失效卡片。

先读取和校验本地 ID 列表，再向受数量限制的公开卡片接口请求有效商品，返回顺序遵循最近浏览顺序。接口只返回公开卡片信息，不返回管理员字段、客户资料或库存明细。

首次浏览若包含当前商品，会显示一张卡片；清空后模块隐藏，直到再次有效进入商品详情。浏览器本地存储不可用或内容损坏时，页面及推荐模块仍正常工作，最近浏览模块按可用记录展示或隐藏。

## 4. 后台管理安排

增加“商品推荐与浏览”设置入口：

| 管理项 | 默认值/行为 |
| --- | --- |
| 推荐模块开关、标题 | 开启，“您可能也喜欢” |
| 最近浏览模块开关、标题 | 开启，“最近浏览” |
| 每个模块展示数量 | 默认 6，可调整并限制合理上限 |
| 自动推荐规则 | 同球队优先，系列/赛季补充，再兜底 |
| 缺货商品是否参与推荐 | 默认参与 |
| 历史保存条数、保留天数 | 30 件、30 天 |
| 清空最近浏览按钮 | 默认提供 |

在商品编辑页增加“推荐商品”区域：

1. 按商品名称、SKU 或分类搜索候选。
2. 多选相关商品，显示缩略图和名称。
3. 支持前移/后移调整顺序、移除关联和恢复自动推荐。
4. 默认“手动优先＋自动补足”；可选择仅使用手动列表。
5. 保存后仅影响该商品的推荐关联，推荐目标的名称、价格、图片等仍由目标商品自己维护。

后台控制模块和推荐关联。个人最近浏览保留在顾客自己的浏览器，后台不显示其他顾客的个人浏览列表。

## 5. 页面和交互实现

- 顺序：商品描述 → 您可能也喜欢 → 最近浏览 → 页脚。
- 桌面 6 列、平板 3 列、手机 2 列；使用本地 480/960 展示图片、固定图片比例和预留高度。
- 新模块使用独立样式范围，匹配截图中的红色价格、原价、优惠框、销售标签位置和间距。
- 复用现有卡片数据与格式化，避免新模块出现币种、语言或金额不一致。
- 商品卡片进入详情选择规格和定制，沿用现有加购、库存和优惠逻辑。
- 推荐模块无候选、最近浏览无可用记录时隐藏对应模块，不放空框或虚构商品。
- 最近浏览加载时预留适当空间并处理失败，避免整页明显跳动。
- 标签、图片替代文字和键盘访问沿用现有可访问性方式。
- 点击卡片进入详情时按现有规则登记访问；加载卡片接口和保存本地历史不重复增加页面访问次数。

## 6. 文件和数据规划

沿用当前 Node HTTP + 服务端模板 + SQLite，不增加新的运行框架或外部推荐服务。

| 位置 | 职责 |
| --- | --- |
| `apps/api/recommendations.mjs`（新增） | 候选筛选、分层排序、去重、手动优先及公开卡片查询 |
| `apps/storefront/product-discovery.mjs`（新增） | 推荐/历史模块模板，复用商品卡片 |
| `apps/storefront/public/recent-products.js`（新增） | 本地浏览记录、去重/过期、清空、多标签同步和加载卡片 |
| `apps/storefront/views.mjs` | 在商品描述后挂接模块，给现有卡片增加可选展示样式 |
| `apps/storefront/public/store.css` | 两个模块的独立响应式样式 |
| `apps/admin/recommendations.mjs`（新增） | 全站开关/规则表单、单品推荐管理 |
| `packages/contracts/` | 规则、商品 ID 列表、数量和排序校验 |
| `database/migrations/` | 手动推荐关联及必要索引；实施时使用下一个可用编号 |
| `tests/` | 推荐算法边界、接口、后台保存及浏览历史行为验证 |
| `docs/`、`docs/screenshots/` | 使用说明、验收报告和桌面/手机截图 |

全站规则存入现有 `settings`。手动关联表计划为 `product_recommendations(product_id, recommended_product_id, position)`，用外键、唯一约束保证关联和顺序。根据实际查询补充分类反向索引；不改动商品、订单和访问表中已有数据。

推荐页直接服务端渲染。最近浏览通过受限的公开卡片接口获取最新资料；接口路径在实施时统一确定，响应复用服务端卡片及语言/货币处理。

## 7. 实施顺序与验收

1. 先实现推荐筛选与手动关联，测试同队优先、排除当前商品、去重、下架过滤及不足时补齐。
2. 接入商品详情，按截图完成第一排推荐卡片与价格样式。
3. 实现本地最近浏览记录和公开卡片接口，完成第二排展示及清空。
4. 加入后台全站设置和单品推荐管理，新建商品默认自动推荐。
5. 验证语言/币种、点击详情后的尺码/定制/优惠流程，以及原有访问统计口径。
6. 完成桌面和手机截图对比、功能验收及使用说明。

重点验收：

- 浏览 A → B → A，最近浏览结果为 A、B；刷新 A 不出现重复项。
- 当前商品在最近浏览第一位，在推荐列表中被排除。
- 分类同时包含球队与赛季时，同球队优先；手动列表优先且自动部分不重复。
- 下架或删除商品后两个模块不显示该商品；改价、替换图片、切币种后展示最新公开数据。
- 过期、超量、损坏的本地记录能正确处理；清空、多标签同步及存储不可用不会破坏商品页。
- 无访问历史、无关联商品、全部缺货等情况按明确规则显示，不产生重复或空白占位卡片。
- 后台更改推荐和开关后生效，普通顾客不能修改配置；不影响定制模板、库存、购物车及订单。
- 桌面一行 6 张，手机两列无横向溢出；卡片价格和现有商城一致。

本轮交付为这份计划。实际编码、数据库迁移、功能测试及截图验收在实施阶段完成；服务器及域名部署继续暂缓。
