## 1. 建立全站定制默认模板（最高优先级）

目标：所有现有商品及后续后台上品、复制商品、批量导入商品，都默认显示“自定义名称 + 编号”和“选择一款臂章贴片”，缺货商品也保留选择区域。

1. 建立全站模板设置，默认启用印字与臂章，印字加价 3 USD / 件；使用已核对的原站图片和选项。
2. 建立“俱乐部”和“国家队”两套臂章模板。国家队商品通过已维护的国家分类关联选择国家队模板；其余使用默认俱乐部模板。具有两类关联的商品使用明确保存的模板选择，避免随分类排序变化。
3. 商品配置采用“继承全站模板 / 单品自定义”。每件商品的两项功能默认保留；单品自定义用于调整臂章名称、图片、费用、字数或模板，不自动关闭功能。若今后有停售选项需求，通过有明确提示的后台管理操作处理。
4. 后台增加“商品定制模板”入口，维护标题、输入示例、字数、加价、臂章图片、名称、排序和可选状态。修改全站模板后，所有继承商品立即生效，无需逐件保存。
5. 新商品表单默认“继承全站模板”，清楚显示当前生效的选项；保存表单、复制商品及 JSON 导入均使用同一个默认策略。
6. 原站抽样风衣没有此配置，但你的要求是全部商品保留，因此新站的风衣等商品也默认启用；是否提供实际印制/贴章由自己的商品运营配置决定。

验收：现有 4,166 件商品都能解析出已启用的两项配置；随机打开球衣、儿童、复古、风衣和短裤检查。后台新建商品且不编辑定制配置，前台仍显示两项功能；全站模板修改一次后，该商品也随之更新。

## 2. 安全迁移现有商品配置

1. 保存数据库一致快照和此次新增/变更媒体清单。已有约 32.53 GiB 原图不重复下载；媒体与数据库的完整备份另按维护流程管理。
2. 扫描所有商品，输出迁移预检：空配置、已有独立配置、分类关联歧义、无有效规格、缺货商品和图片引用问题。
3. 空配置商品标记继承模板；拜仁款保留原有已核实配置，作为单品配置或在确认等价后转为继承。其它管理员维护过的配置保留。
4. 以新增数据库迁移实施，事务内完成，重复执行不重复创建模板或重置管理员改动。迁移编号在实施时按目录实际最大编号继续追加。
5. 迁移不修改自己的库存、规格价格、图片顺序、语言译文或历史订单。无有效规格的商品显示定制区域与明确的不可购买提示，尺码资料另行补齐。
6. 输出迁移后的数量、模板分配、例外清单和回退步骤。

验收：迁移前后商品/SKU/库存/订单数量不变，原有定制订单快照不变；重复迁移结果一致，模板和关联没有重复。

## 3. 商品、购物车和订单统一使用生效配置

1. 服务端增加唯一的“取得商品生效定制配置”入口；商品页、加入购物车、购物车重算、结账和后台预览全部调用它。
2. 印字可留空；非空时每件收取印字费用。臂章按勾选项逐件累加。费用使用整数金额，跟随已有币种/汇率规则换算。
3. 例：基础价 17 USD + 印字 3 USD + 一枚臂章 3 USD = 每件 23 USD；两件小计 46 USD，再按已配置的优惠和运费计算。不得把加价只计一次。
4. 保留当前防篡改校验：服务端读取当前价格；拒绝未知、重复、停用的臂章标识和超长/无效印字。
5. 同一尺码、同一印字、同一组臂章合并；不同定制分行。模板和选项使用稳定标识，改显示名称不会混淆商品或选择。
6. 购物车显示尺码、名字号码、臂章、基础价和加价；修改数量、删除、重新选择及币种切换保持正确。
7. 模板价格变化时重新报价并要求确认当前结账金额；选项被停用时提示重新选择，仍可移除对应条目。
8. 订单保存成交时的模板/选项身份、印字、名称、图片和费用快照；后台订单能直接查看制作信息。后续改模板不改变历史订单。
9. 同一 SKU 的不同定制条目合计检查库存，保留现有幂等下单及取消恢复库存规则。

验收：继承商品和新增商品均能走通选择→购物车→测试结账→后台订单；测试覆盖改价、停用选项、币种切换、分行、合计库存和历史快照。

## 4. 对齐商品详情页

以原站已观察的商品详情为基准，固定语言、币种和视口后对比，先实现一套模板再覆盖全部商品。

- 桌面：左侧竖排缩略图、上下切换、主图计数、正确图片比例；右侧商品标题、销售数据、价格和优惠提示、尺码、数量、定制区、加购/立即购买及服务信息。
- 图片：补核原站放大/预览动作及手机滑动行为，再实现同样的操作；保留原图，使用现有展示副本提升列表加载速度。
- 定制区：输入框高度、标签位置、图片卡片尺寸、选中边框、勾选效果、加价说明和已选内容提示；选择变化时同步按钮金额。
- 下方：商品描述展开、推荐商品、最近浏览区域，使用本地商品与实际浏览记录。
- 销售数量使用新站订单数据；访问人数使用已实现的真实访客统计。配送日期来自后台可维护的发货和运输时效配置。
- 手机：商品图库、尺码/定制卡片、长标题和购买按钮都逐状态验收。

验收：拜仁、国家队、儿童、风衣样本的默认/选择/缺货状态截图可比较；定制区域不会因商品为空配置而消失。

3. 分类：真实商品数量、过滤/排序面板、网格、分页和加载状态；当前采集快照赛季为 1,406 件，不把较早页面的 812 固定写死。

5. 商品卡片快速选择：先核验原站弹层，复用同一个商品定制组件和服务端校验，避免快捷加购漏掉名字/臂章。
6. 逐页检查内部链接、原站图片外链和空模块；正式展示使用本地媒体。

验收：首页→分类/搜索→商品→购物车均可操作；相同语言、币种和视口下模板视觉对齐，手机菜单可用。

继续使用当前 Node HTTP + 模板 + SQLite 架构，不为本次功能重新建立另一套网站。

## 8. 验收顺序与交付

执行顺序：全站模板 → 迁移已有商品 → 后台新增/导入默认继承 → 购物车和订单一致计费 → 商品详情视觉 → 公共布局/列表/搜索 → 购物车/账号/内容/测试结账 → 全站验收。

每阶段交付更新后的本地网址、后台操作说明、变更文件、迁移/采集报告、关键测试结果和截图。验收清单包括：

1. 现有和新建商品均显示两项定制，修改默认模板后继承商品更新，单品配置可保留。
2. 价格按每件累加，前台/购物车/结账/订单一致，USD、GBP、零小数及三小数币种保持正确。
3. 商品图、臂章图、描述图使用本地路径，图库顺序和分类关联仍一致。
4. 订单定制快照、合计库存、后台权限、CSRF 和历史订单均不回归。
5. 桌面 1440×900、手机 390×844 固定截图；关键菜单、轮播、图库和选项状态另截图。
6. 未取得的原站页面、未核验的动态规则及尚未接入的外部服务列入差异清单，逐项处理。

当前已完成的访问统计可在 `/admin/traffic` 查看；相关测试合计 25 项通过。本轮计划不需要再次修改计数功能。

服务器部署是原计划第 8 步，继续不执行。目录结构、媒体引用和迁移会为后续部署保留；拿到服务器、域名后再准备实际部署配置。
