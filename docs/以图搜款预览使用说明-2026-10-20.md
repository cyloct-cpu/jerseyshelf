2026-10-20 已完成本地管理员预览。用户确认暂时没有实拍验收样本，先完成可预览版本。本阶段不向正式站访客开放，不安装线上模型、不更改生产商品或订单数据。

## 打开和试用

- 预览：http://127.0.0.1:3002/search?mode=image
- 后台维护：http://127.0.0.1:3002/admin/image-search
- 已在本机应用内浏览器使用现有本地管理员账户登录，并打开实际搜款结果。
- 若需要再次登录，使用 `storage/bootstrap-admin.txt` 中现有本地凭据；它不公开、不写入本文。
- 可用示例：`storage/image-search/demo.png`，为本站商品图加边框的试验截图。

操作：点击顶部相机或搜索页“以图搜款” → 选图、拖图或粘贴图片 → 在预览画布拖动框选球衣，或使用四个裁剪滑块 → 开始搜款 → 查看候选款 → 打开商品。

结果页支持分类、价格筛选和相似程度/价格排序；筛选和翻页始终保持在本次候选集内。可以点击“更换图片”重新搜索。后台尚未开放时，顶部相机仅管理员可见，访客文字搜索不变。

访客单张图片上限 8 MB、2,000 万像素，支持 JPEG/PNG/WebP。浏览器在选图后预览，点击搜款才上传；方向校正、裁剪和缩放后重新编码，去掉原图元数据。服务器再次验证真实格式、像素和可解码性。原图只在内存处理，不写入媒体库或日志。

查询候选保存在服务端内存，与当前会话绑定，30 分钟后失效；服务重启也会失效。只保留最近一次查询的小缩略图在当前标签页的 sessionStorage 中，供结果页预览，过期后使用该页面时清理。它没有上传到第三方。相似分数不是“同款概率”。

## 本次索引范围

为完成可预览版本，扫描前 500 张有效商品关联图片，成功建立 499 张视觉特征，关联 633 件已上架商品；同一图片可能关联多个款式商品。1 张原文件解码失败，已排除并记录在索引报告中。

这是试验子集，并非全部 4,166 件商品、约 35,000 张图片的完整索引；目前搜不到某款不能认定图库中不存在该商品。未将全部历史图片标注为“索引成功”。

商品图库中的 JPEG/MPO、PNG、WebP、GIF 首帧可以建立索引，明确标为尺码表的图片排除。角色为“未分类”的图片仍需后续补充人工核查，不能声称已全部剔除通用说明图。

## 实现和验证

- 独立 Python CPU 进程运行量化 SigLIP 2 视觉编码器，与 Node HTTP 主进程分离；一次仅执行一个识别请求，繁忙时明确返回 429。启动超时 30 秒，单次推理超时 15 秒，空闲 10 分钟退出模型进程。
- 图库向量按模型和预处理版本隔离，内容哈希缓存；相同图库不重复生成索引。新索引就绪后原子切换，保留上一份向量文件；构建进程通过 SQLite 排他锁避免并发覆盖。失败保留原索引。
- 候选按商品去重，并再次检查当前商品的上下架和图片关联；旧图移除或商品下架后不会继续返回旧候选。
- 已完成浏览器实测：粘贴示例、使用裁剪滑块、提交、缩略图恢复、找到拜仁客场商品，页面截图在 `storage/image-search/preview-result.png`。
- 全站回归命令 `node --test --test-concurrency=2 tests/*.test.mjs`：当次 177 项通过、0 失败、2 项模型集成测试跳过。最初使用默认并发时部分旧测试因启动等待时间不足失败；降低并发后通过，没有修改业务测试的断言。
- 随后使用真实模型运行新增测试，6 项全部通过、0 跳过：默认关闭和文字搜索保留、后台权限、上传格式/大小/CSRF/来源校验、开启门槛、伪文件拒绝、真实检索、会话隔离、候选筛选、下架换图过滤、纯色图空结果及并发上限。

匹配试验报告保存在 `storage/image-search/trial-report.json`。报告明确标为图库合成变形与留出视角的初步评测，`accepted=false`，不能替代顾客实拍和站外无同款图片的人工验收。未开放生产开关，也未生成生产通过记录 `acceptance.json`。

最新试验基于这份 499 图索引，抽取 60 件商品，每件进行 3 类查询，共 180 次。原图合成的截图/压缩和裁剪图主要验证近重复匹配；留出视角测试会排除原查询图片再检索，不等于独立顾客实拍。

| 查询类型 | 未过滤候选前5命中 | 预览阈值0.90下可见前5命中 |
| --- | --- | --- |
| 加边框、缩放和JPEG压缩 | 100% | 96.7% |
| 裁剪图 | 100% | 100% |
| 排除原图后的图库视角 | 93.3% | 58.3% |

当前严格阈值下跨视角召回不足，适合先试用清晰商品截图；不能依据未过滤的排名成绩宣称跨视角功能已达到上线门槛。后续需结合独立无同款样本，优化阈值、局部特征或重排。6 张纯色无细节图都返回空候选。本机热推理及索引检索 P95 约625 ms，不包含网络上传、完整图库或生产并发，也不作为线上耗时承诺。

## 重新启动预览

在项目根目录运行：

```powershell
./scripts/image-search/start-preview.ps1
```

它使用已准备好的隔离依赖、模型和试验索引，仅监听本机 3002 端口，不替换 3001 服务。日志和 PID 在 `storage/image-search/preview-server*`。本机预览和生产是独立数据副本。

## 开发维护命令

首次在另一台机器准备，需要安装 Python 3.11+、pip 和相应平台依赖；模型与运行时文件不会提交仓库。本站 Windows 已完成准备。以下 `$imagePython` 请设为实际 Python 可执行文件：

```powershell
$imagePython='C:/Users/Administrator/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/python.exe'
& $imagePython -m pip install --target storage/image-search/runtime -r scripts/image-search/requirements.txt
& $imagePython scripts/image-search/prepare_model.py
& $imagePython scripts/image-search/engine.py build --limit 500
& $imagePython scripts/image-search/evaluate.py --samples 60
$env:IMAGE_SEARCH_TEST_PYTHON=$imagePython
node --test tests/image-search.test.mjs
```

`--limit 500` 明确生成部分索引；后台“更新图库索引”以及不带 limit 的 build 会构建完整图库，不要将该长时间任务当作本地预览必需步骤。`--force` 会重试失败图片。仅一次重试后仍失败的图片需检查源文件。

正式准备时，选择图库快照与媒体路径、独立进程资源上限，重新生成完整索引，完成至少 120 个独立样本和生产负载验收，再安排发布。线上机器当前为 2 核、约 2 GB 内存，不能直接按本地试验速度承诺线上耗时或并发能力。

后台启用需完整索引以及与该索引 generation 对应的 `acceptance.json` 中 `accepted=true` 的人工验收记录。该记录应包含测试集、各类匹配指标、误匹配、延迟与商城并发测试证据，不能将合成试验报告改名当作通过报告。正式发布前还需确认低分阈值（预览默认 0.90），完成手机与其他语言的浏览器验收。

自动同步配置为 `IMAGE_SEARCH_AUTO_UPDATE=true` 时，每 5 分钟检查源图库指纹，变更时提取新增特征；首版预览关闭自动同步。生产环境需要单独安装平台依赖，保留模型校验资料及上游许可，按实际资源设置进程隔离和内存/CPU限制。

模型来源和固定校验值见 `scripts/image-search/MODEL-NOTICE.md`；原模型官方说明：https://huggingface.co/google/siglip2-base-patch16-224 。
