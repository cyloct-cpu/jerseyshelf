# 立即购买与结账页实施计划

日期：2026-10-15。状态：第一期已实现并验收，执行结果见 [使用说明](立即购买使用说明.md)；下文保留实施方案。

## 目标

参考用户提供的四张截图，在商品详情页补充“立即购买”，顾客选择尺码、数量、印字与臂章后直接进入结账页面，填写收件信息并创建本地测试订单。

本地即可完成，不依赖域名和服务器。截图作为界面参考；截图中的运费、配送国家、支付方式和勾选状态不直接当作本站经营规则。

## 当前实现与需要调整之处

- 商品页 `apps/storefront/product-options.mjs` 目前只有“添加到购物车”，已有规格、数量、印字和臂章表单。
- `apps/storefront/public/store.js` 已处理定制加价和库存状态，但只控制加购按钮，需要同时控制两个按钮。
- `/checkout` 目前只结算会话购物车；`createOrder` 直接读取购物车，下单成功后清空购物车。
- 现有报价具有会话绑定、30 分钟有效期、币种校验和商品指纹，订单具有重复提交保护与事务扣库存。这些逻辑应复用，并补充结账来源绑定。
- 现有结账页缺少截图中的国家下拉、订单备注、配送方案区域与带商品图的摘要，需补充对应存储和后台展示，而非只改样式。

## 一、商品页入口

在印字、臂章和费用提示下方纵向放置两个等宽按钮：

1. “添加到购物车”：白底深色边框，保留原加购流程。
2. “立即购买”：深色背景白字，作为直接结账入口。

两者共用当前表单选择，携带相同的规格 ID、数量、印字和臂章 ID；金额由服务端重新计算。英文分别使用 Add to cart / Buy now，并纳入现有翻译机制。

缺货、数量超库存、无可用规格时两个按钮均不可提交，并显示明确原因。提交中显示反馈，失败后恢复可操作状态。服务端仍独立校验，不能依赖按钮禁用来保护库存。

## 二、立即购买的明确规则

- 只结算当前商品及其所选数量和定制内容，不混入购物车内其他商品。
- 不将商品先偷偷加入购物车，不覆盖或清空原购物车。
- 单个商品购买多件时，仍按本次购买件数计算现有满件优惠和免邮；购物车里未参与结账的件数不累计。
- 点击按钮只创建临时结账记录，不创建订单、不扣库存。
- 刷新结账页保留本次选择；返回商品页提供显式“返回修改”入口，恢复此前选择，修改后生成新报价。
- 不同标签页的立即购买分别使用独立记录；不能共用一个会被后一次点击覆盖的会话字段。
- 下单成功仅完成对应的直接购买记录，原购物车保持原样。购物车结账成功仍沿用当前清理购物车的规则。
- 未登录顾客可直接下单，登录用户的订单归入其账户；登录/退出引起会话变更时，须校验或安全迁移结账上下文。
- 记录过期、商品变更或币种变更时提示重新确认，不能默默按不同金额创建订单。

建议路径：商品页 POST `/checkout/buy-now` → 创建会话绑定的临时记录 → 跳转 `/checkout?purchase=随机标识` → POST `/checkout` 创建订单。具体路径在实现时统一命名。

## 三、结账页面

桌面参考截图采用左侧填写信息、右侧订单摘要的布局，减少普通商城导航对结账的干扰。保留品牌、返回入口和购物车入口。手机改为单列，上方可展开订单摘要，底部为提交按钮，避免横向滚动。

### 联系方式和收货地址

- 邮箱及已有账户登录入口；错误在对应字段旁显示，提交失败保留已填内容。
- 国家/地区下拉、姓名、城市、详细地址、邮编和联系电话。
- 首版使用手动地址表单，不依赖外部地址服务；不放没有功能的地址搜索框。
- 截图里的 Bahrain、Kuwait、Qatar、Saudi Arabia、United Arab Emirates 可作为配送地区配置的候选，最终是否限制为这五国需依据实际配送范围。方案默认不因截图缩小现有可下单范围。
- 国家使用稳定代码存储，名称随界面语言显示。邮编、地区及电话必填规则根据支持的国家和配送方式制定，不能对所有国家套用同一格式。
- “订阅促销邮件”和“保存地址”不默认勾选。首版不新增地址簿或发送营销邮件，因此暂不展示这两个选项；后续实现完整存储/使用流程后再开放。

### 配送方案和备注

- 显示当前配送方案、运费和免邮门槛，沿用后台已有免邮件数、基础运费配置。
- 截图中的 $7 不覆盖本站当前设置；显示“满 N 件免邮，当前运费 X”，避免收费时仍只写 Free shipping。
- 新增可选订单备注，限制长度并在订单详情及后台展示，供店主处理。
- 如实际需要按国家分别计费，作为后续配送规则扩展；不能在仅有统一运费时暗示已经按国家精确报价。

### 商品摘要与金额

- 商品缩略图、名称、尺码、数量标记、印字和臂章及对应费用。
- 显示商品小计、满件优惠、运费、币种和总计，统一使用服务端金额口径。
- 定制费用计入商品金额，单列说明仅帮助理解，不能再重复相加。
- 购物车结账也使用同一套摘要，避免两套页面长期产生差异。
- 优惠码/礼品卡目前没有对应系统，首版不放无效输入框；自动满件优惠照常生效。手动优惠码、礼品卡余额另做后续功能。

### 支付和提交结果

- 首版沿用本地测试订单，明确显示“本地测试，不会扣款”，按钮使用“创建测试订单”。
- 截图中的“货到付款”需要对应支付方式字段、可配送区域和后台处理状态；不能将现有“模拟付款后才可发货”的流程改个标签就当作货到付款。
- 若后续启用货到付款，需支持未收款时发货、签收收款及拒收/取消处理，并在测试环境标注模拟。这不作为本轮立即购买完成的前提。
- 成功页提供订单号、购买明细、收货信息、备注、状态和继续购物入口；游客订单沿用受会话保护的访问机制。

## 四、实现安排

1. 为数据变更生成一致性备份，确认恢复方法；在隔离数据库验证迁移。
2. 新增直接购买临时记录，含随机标识、会话归属、所选商品配置、有效期与完成状态；定期清理过期记录。
3. 抽取统一的“本次结账商品”解析，区分购物车与直接购买来源；金额、定制、促销、汇率、库存和订单快照共用现有计算逻辑。
4. 为报价绑定结账来源及记录标识，限制直接购买必须携带有效报价；提交时验证会话、有效期、配置、价格和库存。对订单备注等新字段补充校验与迁移。
5. 调整订单创建逻辑，保留事务和幂等保护；同一直接购买记录最多创建一笔订单，即使刷新页面取得新的提交键也不能重复创建。取消/退款复用库存恢复规则。
6. 实现双按钮、状态联动与直接跳转，再完善结账布局、错误提示、订单摘要和后台备注展示。
7. 接入中文/英文文案及其他语言回退，完成桌面、手机和 RTL 基础适配。
8. 完成针对性测试、现有订单与购物车回归，记录截图和结果并同步维护说明。

预计涉及商品购买表单、前台 JS/CSS、结账/订单模板、API 路由、订单与报价模块、数据库迁移、后台订单展示及相关测试。具体文件以实现时拆分为准，不需要重写商城。

## 五、验收用例

| 场景 | 预期 |
| --- | --- |
| 普通商品立即购买 | 跳过购物车页，准确进入结账 |
| 选尺码、数量、印字及多个臂章 | 页面摘要和后台订单逐项一致，费用只计一次 |
| 原购物车已有其他商品或相同规格 | 本次直接购买只含当前选择，完成前后原购物车内容一致 |
| 本次购买 2/3、7/8、9/10 件 | 按现有档位计算，仅使用本次结账数量 |
| 两个标签页购买不同配置 | 相互不覆盖，不串单 |
| 刷新、返回修改、重复提交 | 选择可恢复，同一购买记录只有一笔订单 |
| 下架、缺货、最后一件竞争下单 | 服务端拒绝无效提交，不超卖 |
| 改价、改定制、换币种或报价过期 | 要求重新确认，显示新金额 |
| 无效邮箱、缺地址和过长备注 | 对应字段提示，已填信息保留，允许修改重试 |
| 串用其他会话购买标识/报价/订单 | 无法访问或提交，不暴露收件信息 |
| 完成后取消或模拟退款 | 库存只恢复一次，历史快照保留 |
| 中文/英文、390px/360px 手机与桌面 | 两个按钮、地址表单及订单摘要均可操作 |
| 原购物车结账 | 原流程及多币种、满件优惠、定制和后台处理回归通过 |

## 分期与完成定义

第一期完成“商品双按钮 → 独立直接结账 → 截图风格的表单与商品摘要 → 本地测试订单 → 后台查看处理”，包括国家下拉、配送说明和订单备注。

第二期根据经营需求接入真实支付/货到付款、分国家运费、地址保存、邮件订阅、地址自动补全、优惠码或礼品卡，不把这些服务塞进第一期入口改造。

第一期以完整流程、金额、库存、购物车保留、幂等及权限验收通过为完成标准；域名和服务器部署仍在后续阶段。
