# 图片采集与分类管理

2026-10-14 更新。

## 分类增删查改

后台入口：http://127.0.0.1:3000/admin/collections

- 新增：名称、网址标识、分组、排序、封面和是否显示在首页。
- 查询：按名称/网址标识搜索，按分组及正常/已删除状态筛选。
- 修改：独立编辑页保存。改网址标识时同步首页推荐模块和已有轮播链接。
- 删除：可恢复删除。隐藏商城入口与商品分类选项；保留商品本身和原有关联，不删除订单或图片。
- 恢复：切换“已删除”，点击恢复；原来的商品关联重新生效。
- 商品编辑页：分类搜索、新增分类、分类管理、刷新分类列表；刷新保留当前选中项和其他未保存表单内容。新增分类可在新标签页完成，再返回点击刷新。

数据库变更通过 002 及后续版本迁移执行，不需要重建原数据库。

## 本次原站采集方法

原站下载问题已通过本机原有代理通道解决，没有修改系统代理或关闭 TLS 验证。

读取公开页面中实际引用的 `/api/collections/:id/cps` 和 `/api/products/:id`，结合公开站点地图建立清单。默认推荐排序在不同页重复返回商品，改为页面提供的 `published-descending` 固定排序、从零开始的页码和每页 40 条，核对每个分类的唯一商品数。

本次快照：138 个分类、4,166 个商品；2026-27 赛季 1,406 件。此前 812 是早先网页读取结果，不是本次快照总数。商品以原站 ID 去重，分类关联多对多；图片按 URL 建立下载索引、按 SHA-256 保存和去重。

原始文件：`data/source/shoplazza-2026-10-14/`。其中 collections 保存 HTML、pages-fixed 保存正确排序的分页 JSON、catalog-source.json 保存去重商品和关联、assets 保存原图、asset-index 保存每个原图的 URL/哈希/体积/文件路径。旧 pages 目录是推荐排序的尝试记录，不作为最终导入来源。

运行：

```powershell
# Python 3：仅使用标准库
python scripts/capture/shoplazza.py
# 已有商品资料时继续图片下载；已下载文件自动跳过
python scripts/capture/shoplazza.py --assets-only
```

代理使用 `CAPTURE_PROXY` 环境变量指定。当前本机已观察到的代理端口为 7897，其他机器应按其环境配置。`IMAGE_WORKERS` 控制图片并发，默认 16。失败项写入 manifest.json，进度写入 data/manifests/source-download.json。

## 导入与维护

```powershell
node scripts/import/source-site.mjs
# 只补齐图片，不新增商品或分类
node scripts/import/source-site.mjs --images-only
```

导入前建议备份数据库。导入按来源 ID 保持幂等，原图写入媒体库，商品 gallery 使用本地 `/media/` 地址，首页轮播、分类封面及品牌/故事图片关联到本地文件。已有商品名称、价格、运营库存保留；已有后台管理的图片顺序保留。新增商品的库存从零起步，不把原站库存当作自己的库存。

原站部分 slug 超过 250 字符，本地使用可维护的缩短标识；来源表保留完整原路径并用于重定向。来源分类映射保留原 ID，避免后续重复导入覆盖管理员改名或自动恢复已删除分类。

媒体库每页最多展示 48 张图片，支持文件名/来源 URL 搜索。

原图保持原始字节。`scripts/ops/thumbnails.py` 可使用 Pillow 为商品主图生成 480/960 宽度 WebP 展示副本，保存在 storage/media/derived。商城列表优先使用这些副本；图库和媒体原地址仍提供原图。

同一磁盘上的采集原图与正式媒体使用硬链接节约空间；跨磁盘导入会复制文件。两份路径共享原始字节，维护时不要直接改写原图文件。通过后台上传替换图片会生成新的哈希文件，不影响采集快照。

首页品牌、故事和大图模块可在“首页管理”中修改图、标题、文案和站内链接。
