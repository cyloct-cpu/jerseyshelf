# 客户管理实施方案

日期：2026-10-15。状态：方案，尚未实施；本次只检查现有代码与数据库，不修改客户、订单或订阅数据，不发送邮件。

需求更新：用户随后明确以 WhatsApp 沟通成交、识别未成交客户和后续跟进为核心。实施优先级以 [WhatsApp 客户跟进与成交管理方案](WhatsApp客户跟进与成交管理方案.md) 为准，本文件保留通用客户档案、权限与历史订单管理设计。

最新细化：邮箱注册意向、WhatsApp 联系核实、成交回访售后、网站直接下单首次联系，统一采用 [客户四类场景与回访管理方案](客户四类场景与回访管理方案.md) 的状态和实施顺序。

## 1. 现状与目标

当前 `/admin/customers` 只有注册客户列表（姓名、邮箱、注册时间）和邮件订阅列表（邮箱、订阅时间、CSV 导出）。没有搜索、分页、客户详情、编辑、标签、归档和订单汇总。

`users` 保存登录账户，`orders` 保存下单联系人及地址快照，允许游客下单，`subscribers` 单独保存订阅邮箱。现有访问统计使用匿名访客标识，没有真实客户身份关联。当前订单支付仍为本地模拟流程。

目标：每位客户有可检索、可维护的档案；注册、游客下单、订阅均能进入管理视图；客服能查看历史订单、地址、定制要求及内部备注；订阅状态和登录状态分别管理。保留现有订单、商品、定制和翻译行为。

## 2. 管理规则

- “客户”是联系人档案，“账户”负责登录，“订阅”表示营销邮件偏好；三者可关联，但互不替代。
- 注册不自动订阅，下单不自动订阅，后台新增档案不自动创建密码或营销授权。
- 同一档案可以同时有“注册客户、购买客户、订阅用户”等标识，列表不重复计算。
- 游客登记为档案不代表获得登录能力。未核验邮箱不得认领历史订单或合并账户权限；现有订单访问控制保持有效。
- 第一版支持归档与恢复，归档不删除订单，也不等同封禁账户。永久清除和匿名化另设独立流程，在实际交易、退款及保留规则确定后实施。
- 客户姓名、电话、地址、内部备注和印字原文保持原样，不送入现有外部翻译服务。

## 3. 后台页面

### 3.1 客户列表

顶部真实统计：客户档案数、注册账户数、购买客户数、有效订阅数及选定时间范围内新增数。不同指标有重叠，不相加作为总人数；测试订单单独标记。

搜索：姓名、邮箱、电话、客户编号、订单号。筛选：来源、国家/地区、标签、注册状态、有效订阅状态、有无订单、最近下单日期和是否归档。支持分页、排序、清空筛选。

列：客户编号、姓名、邮箱/电话摘要、国家、来源/标签、有效订单数、累计实付参考金额、最近下单、订阅状态、档案状态、详情入口。默认列表不铺开完整收货地址。

批量操作：添加/移除标签、归档/恢复、按筛选导出。批量操作记录操作者、时间、数量和结果，不提供批量默认订阅。

### 3.2 客户详情

- 概览：姓名、联系方式、来源、注册/首次下单/最近下单时间、客户状态、标签。
- 订单：订单号、时间、结算金额及币种、付款和发货状态，点击进入现有订单详情；能查看尺码、数量、名字号码、臂章和加价快照。
- 地址：与档案分开的地址簿，多地址、默认地址；修改地址簿不改历史订单地址。
- 内部备注：追加备注与跟进记录，记录管理员及时间，前台不可见。列表中避免展示敏感备注全文。
- 订阅：邮箱当前状态、订阅/退订时间、来源；保留退订记录，防止导入时重新订阅。
- 操作记录：资料变更、标签、归档、订阅变更和导出事件；不记录密码、令牌、完整地址等不必要内容。

### 3.3 新增和编辑

手动新增档案：姓名、邮箱、电话、国家/地区、语言偏好、标签、地址和内部备注，至少一个可用联系方式；默认无登录账户、无营销订阅。明确新增入口用于线下/客服联系人，不代替顾客注册。

允许编辑联系姓名、电话、地址、标签、备注；“档案联系邮箱”与“账户登录邮箱”区别展示。变更登录邮箱涉及验证和唯一性，不做无提示覆盖。账户密码不展示、不导出，不由管理员填写可见明文。

第一版不包含封禁账户或重置密码；后续如需加入，单独设计权限、会话失效和验证流程。

## 4. 数据来源与去重

1. 注册：创建登录账户，同时建立/关联客户档案，记录注册来源，不自动增加营销订阅。
2. 游客下单：建立客户档案并记录订单来源，保存订单自身联系人和地址快照，不生成账户或密码。
3. 邮件订阅：建立/更新订阅记录；相同规范化邮箱可与档案关联，只有邮箱时名称显示“未填写”，不伪造姓名。
4. 后台新增：建立手工来源档案，不赋予登录能力或订阅状态。
5. 迁移历史：预览注册、订单和订阅的匹配结果；保留旧记录主键及订单权限关系，幂等运行，冲突进入待核对清单。

邮箱去重沿用现有验证与规范化规则，移除首尾空格、规范大小写；不擅自删除邮箱中的点或 `+` 后缀。电话依据国家号码处理，仅电话相同不足以自动合并。姓名、相同收货地址或匿名浏览标识不能作为自动合并依据。

明确匹配才关联；已关联档案的历史订单、已绑定的账户不因另一个人填写同一邮箱而重绑。登录账户持有人与下单收件人可不同，分别保留。疑似重复可提示人工核对，第一版不提供一键合并账户。

客户档案层的业务聚合不改变 `/orders/:id` 和“我的订单”的访问权限。游客后来注册账户时，历史订单认领须经过邮箱验证等归属核验，不能只凭字符串相同放行。

## 5. 订单统计与日常跟进

- 订单数量区分全部、未付款、已付款、已取消/退款以及测试订单。
- 累计金额不把未付款和模拟付款算成真实成交；当前尚无真实付款时显示 0/暂无真实交易，并提供测试统计视图。
- 订单明细显示其原币种；跨币种汇总使用下单时保存的 USD 基准金额，不能相加不同币种，也不能用今天汇率重算历史成交。
- 后续接入真实支付时，实付/退款指标由实际支付和退款事件驱动；有部分退款时按实际金额扣减，不能仅凭订单状态猜测。
- 新客、复购客户可按有效订单自动分组；VIP、批发客户、售后跟进等作为可维护标签。内部备注保留跟进记录，避免覆盖上一条。
- 第一版不自动抓取顾客浏览轨迹、按匿名访客猜测身份或自动发送营销消息。

日常示例：按订单号找到客户 → 检查订单定制和配送资料 → 添加内部跟进备注 → 在订单管理执行发货/售后 → 在客户详情查看后续购买记录。

## 6. 订阅与导出

现有订阅只有邮箱和时间，需要补充状态与事件记录。建议支持待确认、已订阅、已退订；历史订阅标记为旧系统记录，不能虚构已完成邮箱验证。

第一版保留已有订阅入口，增加退订记录和后台管理能力。实际邮件确认、密码重置和顾客自助退订链接需要邮件发送服务及可公开访问的站点，列为后续阶段。未接邮件服务时不显示“已发送成功”。

CSV 导出选择字段与筛选范围，默认不包含完整地址、内部备注；支持 UTF-8，处理以 `= + - @` 开头的单元格，防止表格公式执行。导出客户通讯录不等于允许发送营销邮件；营销名单只包含有效订阅者。

导入安排在基础功能完成后：模板 → 预检 → 重复/冲突报告 → 用户确认 → 导入结果。默认不覆盖已有资料，不恢复退订状态，不授予登录权限；能够安全重试。

## 7. 权限、数据保护和维护

第一版继续使用现有管理员权限，不扩大前台可访问范围；保留会话鉴权、CSRF、参数化查询及输出转义。未来增加客服账号时，将查看、编辑、导出、归档和账户管理拆分授权。

敏感字段的完整查看仅在必要详情中提供；改动记入操作日志。备份、导出文件保存在非公开目录，不能被静态文件路由下载。档案不收集支付卡号或验证码。

数据迁移前生成一致性数据库备份并核对恢复方式。新增表与索引使用版本化 SQL，不把生产资料塞入源码或测试样例。上线时沿用既有数据库/密钥成套迁移方案；本阶段仍不执行服务器部署。

## 8. 源码规划

按实际实施时下一个空闲版本号新增迁移，当前下一号为 018，实施前复查避免与其他功能冲突。

建议拆分：


数据结构建议：新增 `customers`（档案）、`customer_addresses`（地址簿）、`customer_tags`/`customer_tag_links`（标签）、`customer_notes`（内部记录）、`customer_events`（来源与联系事件）；复用 `audit_log` 记录管理操作。`users` 与 `orders` 增加可空的 `customer_id` 关联，原来的 `orders.user_id` 继续负责账户订单权限。扩展 `subscribers` 的状态、来源与时间，必要时另建订阅事件表。

常用索引：规范化联系邮箱、账户/订单客户关联、姓名搜索、标签关联、创建时间、归档状态。客户详情按需查询，列表分页，避免每次页面加载全量客户和订单。

## 9. 实施顺序与验收

1. **资料结构与迁移**：备份、建表索引、导入现有记录、处理冲突，保留订单和登录权限。
2. **核心管理**：列表、搜索筛选、分页、详情、手动新增编辑、标签、备注、归档恢复。
3. **业务联动**：注册、游客下单、订阅自动关联，订单和定制信息、地址及金额统计完整展示。
4. **订阅与导出**：状态管理、退订保护、按筛选导出、批量操作和审计。
5. **回归与交付**：隔离测试验证旧订单、注册登录、定制、币种、导出权限；浏览器实际验收，写使用说明。
6. **后续阶段**：顾客账户资料与地址自助管理、邮箱验证/重置密码、邮件服务、导入及细分权限。需公开站点或服务账号的部分届时单独配置，不阻塞本地后台核心功能。

验收场景包括：重复邮箱不生成重复档案；游客能在后台找到但不能冒认历史订单；更改地址不改变旧订单；同一客户多币种统计准确；测试订单不变成真实销售额；退订后导入不恢复订阅；归档可恢复；后台备注前台不可见；未登录者不能查询或导出客户信息；客户资料不进入翻译队列；旧业务回归通过。
