# 客户管理与跟进使用说明

2026-10-15 已实现。后台入口：<http://127.0.0.1:3000/admin/customers>。仅本地运行，未部署服务器、未发送邮件或 WhatsApp 消息。

## 每天怎样操作

1. 打开“新订单待联系”，优先处理网站直接下单的人，包括游客订单。
2. 打开“注册未成交”和“WhatsApp待核实”，核对号码、聊天及购买需求。
3. 进入客户详情，通过 WhatsApp 或邮箱联系，在“记录沟通”保存结果、备注和下次时间。
4. 在订单页核实收款，收齐后发货，确认实际收货后系统安排回访。
5. 打开“待回访”“售后处理中”“逾期待办”继续处理。

## 四种场景

| 场景 | 入口与行为 |
| --- | --- |
| 邮箱注册未购买 | 注册成功自动建档，保存姓名/邮箱/注册时间，建立首次跟进待办；注册表可选填带国家区号的 WhatsApp 号码 |
| 已注册、不知道是否联系 WhatsApp | 默认“待核实”；人工核对后选“确认未联系”“已建立联系”或“号码失效”，填写依据；没有号码单独标记 |
| 已注册、已下单且已建立联系 | 查看每笔订单是否待付款、部分收款、已收齐、退款、发货；确认收货后建立回访，问题关联为售后事项 |
| 网站直接下单，尚未联系 | 正式订单自动生成“首次联系”和“付款跟进”待办，游客也纳入；订单号去重，重复提交不重复建立任务 |

同一客户可有历史成交和新的未付款订单；售后事项不会因新下单而消失。后台匹配档案不改变订单的账户访问权限：仅同邮箱注册，不能直接查看游客历史订单。

## 工作台和筛选

提供全部、注册未成交、WhatsApp待核实、确认未联系、已联系未成交、新订单待联系、待付款、今日待跟进、逾期待办、待回访、售后处理中、归档和测试客户视图。

可按姓名、邮箱、号码、订单号、标签、国家、联系状态、成交情况、缺号码及注册/登记日期筛选；每页25人。按筛选导出最多10,000人 CSV，默认不包含完整地址或内部备注。CSV 对可能被表格解释为公式的值作了防护。

工作台打开时每15秒更新统计数字，不自动替换列表或中断表单；点击“刷新列表”查看新记录。后台概览也有新订单、今日跟进、回访和售后入口。页面关闭后任务仍在数据库里，但没有手机推送或邮件通知。

工作分组存在重叠，不能相加作为客户总数。仅邮箱订阅与账户注册来源不同，订阅记录不代表邮箱已经验证。

## 客户资料和联系核实

客户昵称、客户邮箱和订单号从注册账户及真实关联订单自动展示，无需手动输入；昵称与邮箱在客户详情中只读。没有下单时明确显示“尚未下单”，不虚构订单。手动新增入口仍可补充站外联系人。

已保存收货资料后，自动同步收件人姓名、国家/地区和手机号码；优先采用最近的正式订单，缺少正式订单时采用最近的测试订单。注册昵称与联系姓名分开保留，填写收件人姓名不会改变账户昵称。跟进和售后表单自动选中最近关联订单，多笔订单可切换。

联系姓名、手机、国家/地区、WhatsApp号码、语言偏好、负责人和标签仍可手动补充；手动修改过的字段不会被后续同步覆盖。需要重新使用平台资料时，点击“恢复自动填充资料”。历史客户在启动时自动补齐资料，已有手工修改尽量保留；旧订单地址与账户权限不变。

手机号码保留客户填写的原始格式。普通国内收货电话不会被猜测为国际WhatsApp号码；已填写的注册WhatsApp号码优先保留，联系状态仍需实际核实。未提交保存的结账表单不作为已保存收货资料。

WhatsApp号码须包含国家区号（如 `+44 …`），保存时规范化。号码修改后自动回到“待核实”。“打开WhatsApp”只是打开聊天，不修改联系状态、不发送消息。确认已建立联系必须有号码并填写核实说明。

“记录沟通”可选已实际联系、已联系未回复、联系失败或仅内部备注。首次联系待办只有选择“已实际联系成功”并关联该待办才能完成；未回复可继续保留或延期。跟进时间按北京时间显示和填写，数据库统一存 UTC。

“停止普通购买跟进”会取消现存普通购买跟进和不关联订单的首次联系任务；实际订单、回访和售后服务仍可处理。归档保留资料和全部历史，可恢复。

## 订单模式与实际收款

进入“客户管理 → 管理设置”：

- **本地测试模式（默认）**：保留已有测试流程。测试订单单独标记，不计真实成交，也不生成真实订单联系提醒。
- **正式外部收款模式**：仅影响之后的新订单；提交后待付款，不自动扣款。新订单生成客户及联系/付款待办。原有测试订单不会被转成真实成交。

正式订单详情中可登记实际到账或已完成退款，填写订单币种的金额、方式、参考号、实际时间，并勾选已人工核实。客户说已付或提供图片不自动算到账。

支持部分收款，收齐后才能发货。重复提交同一收款请求不会重复记账，同一订单的同类参考号重复也会拒绝；金额须符合币种精度，不能超收或超退。退款保留独立流水，历史成交时间保留。跨币种款项应先人工核实换算，本模块仅按订单结算币种登记。

正式订单下单时沿用现有库存扣减规则，未付款且无待退实收金额的未发货订单可取消并恢复库存；重复取消不能再次恢复。已发货退款不自动将实物加回库存。

当前没有线上支付机构自动回调、自动对账或自动转账，全部为商家实际到账后的人工核实。

## 发货、回访与售后

1. 收齐款项后填写物流单号、标记发货，生成配送确认待办。
2. 核实实际收货后填写收货时间，系统关闭配送待办，按设置天数（默认5天）建立回访；发货本身不会被算作已收货。
3. 回访完成填写结果，可继续建立下一项任务。
4. 创建售后须关联该客户的订单，记录尺码、印字、物流、退换货或其他问题。
5. 售后状态支持新建、处理中、等待反馈、已解决和已关闭；解决/关闭会完成对应售后待办，重新开启会恢复待办。处理过程保留在时间线。

## 数据与维护

- `database/migrations/018-customer-management.sql`：档案、任务、事件、售后、收款与订单关联。
- `apps/api/customers.mjs`：档案/来源关联、查询统计、跟进和售后。
- `apps/api/customer-profile.mjs`、`database/migrations/020-customer-profile-autofill.sql`：注册/收货资料同步、手工修改保护及自动资料恢复。
- `apps/api/customer-payments.mjs`：收款幂等、金额校验、正式订单状态、回访联动。
- `packages/contracts/customers.mjs`：状态、号码、时间验证。
- `apps/admin/customers.mjs`：工作台、客户表单/详情及正式收款界面。
- `apps/admin/public/customers-admin.js`：工作台统计刷新。
- 原有注册、订阅、结账入口调用业务模块，现有订单权限不变。

客户、地址、沟通记录、售后及收款记录只在受保护页面读取，不加入公开文案翻译队列。客户管理变更、导出和核实收款记录操作人及时间；事件时间线保留历史。

改造前备份：`storage/backups/2026-10-15T13-39-47-419Z-before-customers`，包含数据库、源代码及已有凭据加密文件，不重复复制媒体库。恢复旧版本需要配套恢复旧数据库和旧源码，不可仅删除迁移记录。

专项测试：`tests/customer-management.test.mjs`，隔离数据库演练四类客户、权限、去重、收款、回访、售后及退款；不向真实客户发送消息。
