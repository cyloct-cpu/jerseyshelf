# 订单跟进、售后与物流对账

已实现后台人工闭环。入口 `/admin/service`，侧栏“售后与对账”；订单详情也有对应操作。全部国家的原有国家选项保持可用。本功能不向客户或物流商自动发消息，不执行银行转账。

## 未确认订单

正式未发货订单自动纳入确认跟进。默认提醒间隔24小时，可在工作台修改为1至720小时。负责人、联系结果、下一次跟进时间及每次操作历史均保存。今日/逾期未确认数量在后台显示，页面打开时定期刷新数量。

货到付款必须先在发货资料卡核实地址、电话和代收金额才可标为已确认。未付款不是自动取消理由；取消继续采用订单处理区的人工操作，未发货库存仅恢复一次。

## 售后申请

签收后从订单详情选择商品和数量，创建仅退款、退货退款、换货或补发申请。支持负责人、原因及证据说明，创建后可上传私有图片。图片最多10张、单张3MB，支持PNG/JPG/WebP/GIF，只有登录管理员能访问，图片随数据库备份保存。

累计有效申请数量不能超过商品已签收及购买数量；审核拒绝后释放该申请占用数量。换货、补发完成后不会再次占用库存。

退款上限使用原订单商品单价、原优惠分摊及定制快照，不使用现价。优惠按原商品金额分摊并以整数最小货币单位计算。货到付款币种不同于订单展示币种时，商品退款上限按发货前核定的代收总额比例换算，不读取实时汇率。

后台先审核退款总额以及其中可退运费；商品上限、累计可退运费和实际收到的客户货款均限制实际退款。定制费是否可退和运费是否可退提供人工审核或排除选项。默认退货期限为0，表示商家逐单审核，未给客户承诺某个期限；确认经营规则后可配置期限。

## 退货验收与换货

退货退款/换货审核后进入待寄回，可登记退货运单。每次验收分别填写实收数量、其中可重新销售的数量，只有可售数量恢复库存；损坏数量保留记录，不进入可售库存。

数量不足时可继续等待并分次验收；经核实，也可按已收到数量结束本次验收并减少批准退款。未收到数量不恢复库存。核实结案后的申请保留原申请数量与实际实收差异，后续额外请求须人工核对，不能通过另开相同商品申请重复退款。

换货可选同一商品的其他有效规格；按实际收到的商品数量换货。补发按申请数量发出。实际发出后记录新运单并扣减选中规格的库存，不覆盖原退货运单；库存不足整次操作回滚。

## 退款记账

审核、必要验收完成后，登记实际退款对象、退款方、币种、金额、方式、参考号、时间及凭证。此处只记录已核实完成的退款，不自动向客户转账。

- 商家直接退款：保留商家转款记录，不减少物流商尚需结算的货款。
- 物流商退款：若从尚未结算的代收货款中扣除，明确勾选，系统减少待回款，防止物流商退款后又按原金额结算。
- 跨币种退款：同时记录核定退款币种的金额、客户实际收到的币种和金额，凭证说明包含双方确认的换算依据。

分次退款累计，不能超过审核金额及核实客户货款。重复请求及重复参考号不能增加金额。物流回款后续登记不会把已有退款订单重新标成未退款。

## 代收与回款差额

订单详情可登记实际代收及更正，核实依据必填。实际金额与核定金额不同自动建立差额单；零代收也可记录。不凭签收猜测已收款。

更正代收不能使货款小于已经回款、已扣除退款或已退给客户的金额；涉及此前财务记录时先核实账目，保留处理历史。

手工差额单支持代收差额、物流商未转款/少转款、扣费不符和跨币种差异，保留负责人、应为/实际金额及依据。关闭差额单需填写处理结果，不会自动更改已经核实的现金账。

物流商私下转款继续使用人工回款登记，新增实际转款币种、实际到账金额及跨币种换算说明；核定代收币种的结算、扣费、净额与实际转款原币种分别保存。

## 验证与边界

新增迁移 `024-order-aftersales.sql`。历史订单、代收/回款流水、原收货快照保留。实际业务仍由商家审核；本轮未新增客户自助售后入口，也未接自动物流或银行接口。

商品售后、库存及退款与原有未签收退回库存恢复相互限制，不能对同一商品重复恢复。预先付款订单原有退款入口也会扣除新售后已退金额，避免两个入口重复退款。

专项验证见 `tests/aftersales.test.mjs`，覆盖权限、快照、数量与金额限制、私有附件、分次退款、退款抵扣物流回款、跨币种转款、差额处理、损坏/短缺验收、换规格及重复发货防护。

核实物流商多收款后，可从对应差额单建立专用退款申请，不占用商品退货数量。该申请需人工审核和登记实际退款凭证，已申请的多收金额不能重复申请退款。新商品售后也会关联客户管理的售后记录。
