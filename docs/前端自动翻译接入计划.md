## 目标与推荐方案

后台界面继续使用中文，管理员用中文维护轮播、公告、分类、商品和其它公开文案。顾客首次访问时自动匹配其浏览器偏好语言，也可使用现有语言搜索菜单手动选择；前台按最终语言显示完整的对应语言版本。现有商品和以后新增、批量导入的商品统一适用，管理员仍可人工修订。

## 完整英文版与缺失译文处理

1. 初次切换新版前，预生成全部已发布公共文案及 4,166 件上架商品的必需英文内容，并生成缺失字段报告。报告清零、样本与全站页面检查通过后，再发布新版英文入口。
2. 英文内容解析优先使用有效人工英文稿，其次使用当前源版本的自动英文稿，或经核对本来就是英文的源内容；不得默默返回中文。
3. 中文“保存”与各语言的“发布状态”分别记录。管理员保存成功即保留中文原稿，翻译完成并通过校验后发布对应语言版本；排队或失败必须在后台显示出来，不能标成已完成。
4. 已有页面更新时可继续提供此前完整的已发布英文文案，明确记录待更新状态；涉及商品身份、配送/售后承诺或其它无法安全沿用的变更，需同步译文后发布该版本，不把过期内容冒充当前版本。
5. 新增商品或内容的英文尚未完成时，保留为英文待发布，不把中文条目插入英文列表。后台提供失败重试与人工补齐；直接访问未就绪的英文资源时只能显示明确的英文状态提示，不能伪造译文或夹带中文。
6. 翻译服务中断时，已发布英文从本地缓存继续展示；新的翻译任务排队或暂停，不让浏览、购物车和已有商品下单依赖外部服务实时响应。
7. 其它语言完成覆盖前，明确标记其准备状态；不能只更改菜单名称就宣称全站已经是对应语言。

不以隐藏正常描述、删除商品名称、把所有商品替换成相同英文占位词等方式通过“没有中文”的检查。目标是完整、准确的英文内容。

Google 官方说明：Basic 支持标准文本翻译，Advanced 另外提供术语表等能力。首期球队及商品术语通过本地术语规则维护，不依赖 Advanced 的云端术语表。[翻译接口说明](https://docs.cloud.google.com/translate/docs/translate-text)

## 首次访问自动选择语言

语言识别与内容翻译分别实现：先确定顾客希望看哪种语言，再读取该语言的译文。

推荐优先级如下：

1. 有效的页面语言参数，用于显式语言链接或后台预览；临时预览不改写顾客的长期偏好。
2. 顾客在语言菜单手动选择并记住的语言，沿用现有一年 Cookie 有效期。
3. 浏览器 `Accept-Language` 中匹配到的、网站已启用的语言，按偏好权重解析。
4. 后台配置的默认前台语言；面向国际顾客建议英语，可按运营需要改为简体中文。

顾客手动选择始终优先，自动识别不能在刷新、切换商品或再次访问时覆盖它。浏览器语言请求头反映语言偏好，不代表国籍；这个机制与尊重显式选择的原则见 [MDN 说明](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Accept-Language)。

常见匹配示例：

| 浏览器偏好 | 前台选项 |
| --- | --- |
| `en-US`、`en-GB` | 英语 `en` |
| `ja-JP` | 日语 `ja` |
| `de-DE` | 德语 `de` |
| `zh-Hans`、`zh-SG` | 简体中文 `zh-CN` |
| `zh-Hant`、`zh-HK`、`zh-MO` | 繁体中文 `zh-TW` |
| 不受支持的首选语言 | 继续匹配下一种偏好，最终使用网站默认语言 |

匹配时保留有意义的文字差异，忽略被明确拒绝的 `q=0` 项，限制输入长度；无效请求头不能导致页面错误。前台在服务器首次输出时就确定语言，减少整页先中文再切换的闪动。

现有搜索框和 109 项语言菜单保留，增加“自动（跟随浏览器）”，供顾客清除手动偏好、恢复自动识别。页面 `lang`、文字方向、公共卡片接口与其它页面使用同一识别结果；共享缓存也必须区分语言，不能串用不同顾客的页面。

“本国语言”首期按浏览器偏好实现，不申请设备定位、不把国家强制对应为一种语言。以后有服务器和域名后，如仍需要按 IP 国家辅助判断，可再接入可信服务器侧国家信息，只在缺少明确语言偏好时辅助匹配，不能覆盖手动选择。

## 中文保存与译文更新

截图中的首页轮播优先接入，后台操作保持简单：

1. 管理员照常输入中文标题、介绍，选择原有图片和链接，点击“保存并更新首页”。
2. 保存中文原稿成功后，为启用的预生成语言创建去重翻译任务，不等待外部接口，也不让翻译失败导致原稿保存失败。
3. 后台显示各语言“待翻译、处理中、已完成、失败、待复核”，可选择语言预览、重试或修订译文。
4. 顾客首次被自动匹配或手动选择某种语言后，读取该语言已发布的完整内容；缺失译文按上述待发布规则处理，英文模式不回退中文。
5. 修改某一句中文，仅更新那一字段的译文。调整轮播顺序、替换图片或修改链接，不重复翻译未变的文字。
6. 新增轮播、公告、分类、商品、文章和导入内容走同一套流程。原有英文或中英混合的采集内容按实际源语言处理，不批量覆盖原始资料。

自动译文不会覆盖人工修订。原文变动后保留旧人工译稿供对照、标记待复核，前台使用与当前源版本对应的有效内容；过期任务不能把旧结果写回新稿。

## 顾客与上品流程

1. 顾客切换语言，保留当前页面、搜索筛选和货币选择，语言偏好沿用现有记忆方式。
2. 按字段选择当前目标语言的有效人工译文、自动译文或已核实的同语言原文；英文不得落回中文，其它语言的缺失项也必须计入覆盖报告。简体中文界面中的英文源商品同样纳入译文任务，不能把所有源文本强制当中文。
3. 页面读取已发布的语言版本。翻译任务由保存、导入或补齐操作提前生成；缺失时可提交去重任务，但不能因此向顾客输出一份混合中文的英文页。任务完成后发布对应内容，不重载整页或清空顾客已选尺码、印字和臂章。
4. 新增或导入商品保存成功后，对运营启用的预生成语言建立翻译任务，保存商品无需等待外部接口。
5. 修改原文时，只重新翻译发生变化的字段。人工译文标记待复核并保留，不自动覆盖；旧自动译文不得伪装成新版本译文。
6. 商品描述折叠、图库、尺码、定制、购物车、价格和货币逻辑继续正常使用。

## 语言策略

- 保留现有语言菜单架构，逐一核对本地语言代码与服务支持代码，建立映射和可用状态。
- 第一批将英语作为完整版本先验收，再分批扩展西班牙语、葡萄牙语、法语、德语、意大利语、日语、韩语、阿拉伯语、俄语。
- 其余受支持语言按运营启用和用量预算生成并缓存；后台调整名单和就绪状态。未完成覆盖的语言不应标记为全站就绪。
- `ha-Arab` 等文字变体不能直接等同于普通语言代码。没有对应能力的选项应明确显示可用性，不能用其他文字译文冒充；上线前形成完整映射报告。
- 原文为中英混合时按内容段检测源语言；赛季、品牌和球衣术语先做样本验收，避免错误转译。

服务语言能力以 [Google 官方支持列表](https://docs.cloud.google.com/translate/docs/languages) 和实际接口核对结果为准，不能仅凭现有菜单有 109 项就承诺全部可自动翻译。

| `apps/api/translation-worker.mjs` | 有限并发、预算预占、重试及重启恢复 |
| `apps/admin/translations.mjs` | 中文设置、任务状态、预览和人工修订界面 |
| 现有 storefront 文案/商品本地化模块 | 按资源字段读取目标语言；输出时继续转义，保留页面布局和购物选择 |
| `database/migrations/下一可用编号-*.sql` | 增量建表，不重置商品、图片、分类、库存、定制和订单；当前最大编号为 014，实施前再核对 |
| `scripts/i18n/` | 公开文案盘点、逐语言缺失报告、英文页中文残留扫描和保留项清单 |
| `tests/` 与 `docs/` | 语言协商、增量任务、缓存、完整英文及回归检查；配置、备份和迁移说明 |

资源用“类型 + 稳定 ID + 字段”定位，原文哈希判断版本。例如一张轮播的标题与介绍独立管理，移动到另一位置后仍保持各自译文。译文缓存同时包含服务、源/目标语言与术语版本；数据表保存状态、版本和更新时间，不把译文散落在页面模板里。

未来部署时，应用启动脚本和后台任务一并规划。未配置有效服务时，先通过测试适配器验收识别、队列、缓存与页面流程，不伪造已完成的真实翻译，也不发起付费调用。

## 成本控制与初步估算

截至本计划核对时，Google 标准 NMT 文本翻译按送入接口的字符及目标语言计费：每月前 50 万字符通过最高 10 美元月度抵扣覆盖，之后通常为每百万字符 20 美元；Basic 与 Advanced 的相关抵扣合并计算。[官方价格](https://cloud.google.com/products/translate/pricing)

以下保留扩展至 10 种目标语言的预算情景；首期只先完成英语，执行前按源语言和缺失量重新预估，不直接启动全部语言。以去重的 154,082 个商品文本字符、每段均翻译至 10 种目标语言作粗估：

- 总量约 1,540,820 个字符，抵扣前约 30.82 美元。
- 若当月 50 万字符抵扣尚未使用，约 20.82 美元。
- 上述仅估当前商品名称和专属描述，不包含界面、分类、政策等其他内容、后续修改、额外调用和税费；剔除源语言与目标语言相同的任务后，实际量也可能减少。
- 公共描述每种语言只计一份，不乘以 4,166；缓存命中不再次调用服务。

后台提供字符用量、预估费用、失败次数与月度预算。预算以应用内字符额度控制并预留并发消耗，达到上限暂停新任务，继续提供已有缓存；外部账单仍以服务商实际计量为准。批量开始前先显示字符预估，不默认一次性翻译所有语言。

## 验收标准

- 后台仍为中文；截图中轮播的中文标题和介绍，在英文、日文等语言下均能显示对应译文，图片和链接保持原配置。
- 首次访问按浏览器偏好匹配；手动选择在刷新、切换商品和再次访问时保持；“自动”可恢复识别；无效或不受支持的偏好有正确回退。
- 调整轮播顺序不会串用译文；改图片/链接不重新翻译；更改标题只使对应标题的译文失效。
- 切换语言后，商品列表、详情、搜索、推荐、最近浏览及购物车使用一致译文，公共描述也随语言切换。
- English 模式逐页检查轮播、公告、所有商品卡片标题、展开后的完整描述、定制选项、购物车与结账，以及登录/表单校验、缺货、空搜索等状态；除明确保留项外不得残留网站中文文案。
- 检查前端脚本生成的文字、图片 alt、按钮可访问名称、页面标题和元描述，避免仅初始 HTML 是英文、交互后又出现中文。
- 商品英文必需字段覆盖全部待发布商品；不能仅靠首页 6 件或少量抽查宣称 4,166 件全部完成。未通过的资源和字段必须出现在后台遗漏报告中。
- 检查实际译文准确性和术语一致性，不能只用“未匹配到汉字”作为英文正确的依据。
- 人工修订优先；相同文案复用；刷新页面和多顾客访问不重复调用外部翻译。
- 新增、修改和导入商品进入正确任务；服务重启可续跑，失败可重试，原文更新不会被旧任务覆盖。
- 服务超时、断网、额度耗尽时仍可浏览及下单，不显示空白内容。
- 手机端、阿拉伯语 RTL、描述展开/收起、尺码与定制功能正常；价格、币种和数量不被改写。
- API 凭据不会出现在网页、浏览器请求和日志中；顾客输入不被当作待译商品文案发送。
- 先核对至少 20 件涵盖不同球队、版本、中文/英文/混合标题的商品，确认术语及数字准确，再执行全量任务。

## 开始实施前的依赖

需要选定服务商，准备已启用 Cloud Translation 的 Google Cloud 项目、计费账户和受限 API 凭据，并设定首批语言与字符预算。凭据应在实施后的后台安全配置，不需要写进聊天或源码。部署环境需验证能访问官方 API，不能默认依赖本机开发代理。[官方开通说明](https://docs.cloud.google.com/translate/docs/setup)
