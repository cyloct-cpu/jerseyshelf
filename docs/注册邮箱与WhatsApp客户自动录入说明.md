# 邮箱注册、WhatsApp授权与客户自动录入

实施日期：2026-10-16。功能运行在现有本地商城，未部署服务器、未接入发信服务、未发送真实WhatsApp或营销邮件。本店既有点击联系号码及翻译配置保持原样。

## 客户操作

入口：[创建账户](http://127.0.0.1:3001/account/register)，或商城顶部“账户 → 创建账户”。

1. 填写名、可选的姓、邮箱及至少12位密码；支持显示/隐藏密码。
2. 可以只用邮箱注册。WhatsApp号码及联系授权均为选填，授权默认不勾选。
3. 号码可使用“国家区号＋本地号码”，也可以直接输入以 `+` 开头的完整国际号码。常见国家区号可从输入建议中选择，其余区号可以直接输入。
4. 注册WhatsApp联系许可与邮件新品优惠订阅分开勾选。未勾选也可正常注册。
5. 注册成功页提供WhatsApp咨询、继续购物及进入账户入口。由客户自行打开聊天并确认发送；不会自动发消息。
6. 从结账页发起注册时，成功后直接返回原结账，保留已有购物车、购买记录及订单权限。

输入错误时在原页面显示错误并保留姓名、邮箱和选项，密码不回显。重复邮箱不能覆盖已有账户，提示使用登录。注册会更换会话令牌，账户密码使用既有scrypt哈希，不保存明文。

## 自动录入客户系统

注册操作在数据库事务中完成：

**创建客户账户 → 建立或关联CRM档案 → 录入姓名/邮箱/时间/号码/语言 → 保存授权记录 → 建立一次首次跟进待办。**

号码统一为带国家区号的数字。系统分别保存注册资料与CRM联系资料：手动补充的联系姓名、负责人、标签、备注及手工覆盖字段保留。已有收货资料继续按原逻辑同步。

关联已有邮箱的CRM档案只用于后台客户管理，**不会把该邮箱过去的游客订单授予新注册账户**。订单访问仍由原账户或游客原会话控制。

注册状态不代表邮箱已验证；当前账户和后台显示“邮箱未验证”，后续可单独接入邮件验证服务。填写WhatsApp号码不代表已验证号码、已添加联系人或实际建立沟通。

## 后台使用

入口：[客户管理](http://127.0.0.1:3001/admin/customers)。新增快捷分组：

| 分组 | 规则 |
| --- | --- |
| 新注册客户 | 最近7天注册的客户 |
| 注册缺WhatsApp号码 | 注册账户未填写WhatsApp号码 |
| 注册有号码未授权 | 已留号码，许可为未知、未授权或已撤回 |
| 注册已授权待联系 | 当前注册号码已授权，尚无该号码的实际回复或已核实联系 |
| 注册已点击聊天 | 客户已在登录状态下打开过本店WhatsApp入口，不代表发送成功 |

客户列表分别显示注册WhatsApp号码、注册授权及CRM联系状态。客户详情的“注册资料与联系授权”面板显示注册资料、邮箱验证状态、许可范围、授权来源、文案版本、语言和变更时间；支持后台撤回已有许可，不能由后台勾选代替客户同意。

原有注册未成交、新订单待联系、付款跟进、回访和售后继续工作。统计分组可以重叠，数量自动刷新，列表不强制跳页。

无订单的注册客户在未授权时，后台不会通过该注册号码发起主动联系。客户仍可自行使用网站WhatsApp入口咨询。注册授权不触发Cloud API自动发送，第一版仍通过后台预览和App/Web人工确认发送。

## 修改与撤回

客户登录“我的账户 → 联系资料与授权管理”可以：

- 修改名、姓及注册WhatsApp号码；注册邮箱保持不变。
- 取消勾选并保存，撤回注册WhatsApp或邮件优惠订阅。
- 修改号码后先保存，再重新勾选并保存授权；原号码注册许可撤回，新号码不会继承旧号码的授权。
- 清空号码时同步清除自动采用的注册号码；后台已手工覆盖的独立联系号码继续保留。

邮件取消订阅使用 `subscribers.active=0`，保留来源记录。没有勾选新品优惠时不会为本次注册新增优惠订阅；历史邮件订阅不被推断为注册WhatsApp许可。

注册咨询/账户服务授权与订单联系许可分开保存。修改注册号码和撤回注册授权不会改写历史订单快照，也不会借注册许可放开未授权订单的API发送。订单服务许可仍按原订单规则管理。

当未来收到签名有效的官方 `STOP`、`UNSUBSCRIBE`、`退订` 或 `停止` 消息时，撤回该号码的注册WhatsApp及既有订单渠道许可，取消尚未提交的订单排队消息；历史记录保留。非文本消息仍只保存类型，不下载附件。

## 历史数据

启动时只补齐尚未处理过的历史注册账户：保留完整旧姓名作为“名”，不猜测姓；从已有明确注册来源读取号码；缺失的资料保持空。

没有授权依据的历史记录一律标为“授权未知”，记录本次补齐来源及时间，不伪造原始授权时间、真实回复或注册时间。迁移标记保证重复启动不覆盖客户后来修改的资料，也不重复生成授权事件或首次跟进待办。

## 文件规划

| 路径 | 职责 |
| --- | --- |
| `database/migrations/022-account-registration.sql` | 注册资料、当前许可及授权历史表、邮件订阅状态 |
| `packages/contracts/registration.mjs` | 字段验证、授权文案与版本、状态名称 |
| `apps/api/account-registration.mjs` | 注册事务、账户资料同步、历史补齐 |
| `apps/api/account-permissions.mjs` | 许可状态及历史、撤回、客户点击记录 |
| `apps/storefront/account-registration.mjs` | 注册、成功页、账户偏好和顶部菜单 |
| `apps/storefront/registration-translations.mjs` | 新页面英文词典，接入既有多语言系统 |
| `apps/admin/registration-consents.mjs` | 后台注册资料、许可与变更历史 |
| `tests/registration.test.mjs` | 隔离数据库HTTP流程与模拟回调测试 |

授权文案更改含义时，应更新 `registration-service-v1` 或 `email-marketing-v1` 版本，保留已有历史。私人姓名、邮箱、号码和授权历史不进入外部自动翻译队列。

修改前备份位于 `storage/backups/2026-10-16T06-33-56-132Z-before-registration`，包含数据库、源码及现有配套加密文件；媒体保留原目录。恢复时先停止商城，并成套恢复数据库、源码和对应密钥。

## 验收记录

使用隔离数据库、虚构客户、虚构号码及模拟Meta回调，验证注册即自动录入、不同授权分组、账号权限、重复提交、资料更新、撤回、退订及历史迁移；没有向真实客户发信。

注册专项14项通过；全量145项通过。全量在本机使用 `node --test --test-concurrency=3 tests/*.test.mjs`，避免大量并发服务争用资源导致旧测试的5秒启动等待超时。手机390px布局无横向溢出，授权默认未勾选，注册按钮可见时浮动客服按钮自动避让。

商城使用项目根目录 `启动网站.ps1` 在后台持续运行，默认端口3001；日志位于 `storage/server.log` 和 `storage/server-error.log`。关闭执行会话后仍可继续访问。如电脑重启，可再次运行该脚本。
